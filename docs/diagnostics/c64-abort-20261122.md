# C64 terminal-call diagnostic (not a release)

On v0.8.0 C64 image `d5a0b0f35ac7fc51`, settled Elite with turbo off and sound on
recovered to Master during read-only web status sampling. Master retained:
`reason=watchdog, phase=6, pc=10020ee4, cfsr=00000000, bfar=e000ed38`.
The matching release ELF places 10020ee4 at `_exit`'s `bkpt 0` instruction.
The frontend was the last recorded phase. Neither a networking bug nor a Bluetooth
bug is established by this record. BFAR is not a valid fault address with this CFSR.

An 8-second watchdog is the recovery mechanism, not necessarily the original
cause. SDK assertions, panic, abort and exit may all converge on a terminal path.
The diagnostic candidate keeps the release optimisations and watchdog recovery,
and enables `C64_ABORT_DIAG` (default OFF). It captures terminal calls before
formatting/logging and without allocation, flash writes or lockout. Recovery is
accelerated to one second once the record is saved. The caller is a return address;
assertions additionally retain their line and expression pointer, panic its format
pointer, and exit its status. Keep the exact ELF to decode pointers and symbols.

Scratch registers 0..3 carry the record through the existing launcher fallback;
4..7 remain owned by the SDK. Master reports `c64_failure.reason=terminal-call`,
`kind`, `frontend_stage`, `core`, `phase`, `caller`, `line`, and `detail`.
A simultaneous terminal failure on both cores can race; this is not a backtrace.
If no hook fires, the existing watchdog/hardfault record remains available.

Kinds: 1 abort; 2 exit; 3 _exit; 4 assertion; 5 panic; 6 hard assertion.
Stages: 0 outside frontend; 1 menu; 2 preferences; 3 USB; 4 API; 5 drive/save;
6 network; 7 Bluetooth; 8 controller. Stage tracking is once per frame, not per
emulated instruction, and is compiled out when C64_ABORT_DIAG is disabled.

Flash the separate combined test UF2, power cycle, select C64 and leave Elite in
the same settled state, with turbo off and the same sound/LED/input settings.
If Master appears, capture `/api/status` before another reset or machine switch.
Do not deliberately trigger an abort through a public web command: none is added.
Use `tools/c64_abort_decode.py status.json candidate-c64.elf` with the matching
ARM tools. Defer D81 loading until the idle failure is captured.

Host sanitizer tests exercise all six terminal hooks and the actual Master JSON
decoder, checking frontend/core/line preservation, SDK scratch isolation and legacy
fault reporting. The diagnostic subsequently captured an actual hardware panic
on image `f75350f0fc1f619b`: caller `10033b59` and detail `10068fa4` resolve in
its retained ELF to lwIP `sys_timeout_abs` and the exhausted `MEMP_SYS_TIMEOUT`
assertion. See [the timer-pool diagnosis](network-timers-20261122.md). Caller
capture remains enabled in the
[verified startup/DMA checkpoint](../../checkpoints/four-machine-startup-dma-20261122/README.md).
v0.8.0, its downloadable firmware and previous reference tags are unchanged.

# C64 T64 program loading

In Commodore 64 mode, choose a `.t64` from the SD card list, or drop it onto the
web page at http://8bitretro.local. ZIP uploads containing a T64 also work.

A single-program archive loads automatically after a C64 reset. If its payload
is a valid tokenised BASIC program at `$0801` (including a BASIC `SYS` startup
stub), it also runs. Other payloads load without an automatic start command.
Pressing a key during the startup delay cancels the pending automatic load.

For archives containing several programs, the **T64 programs** panel lets you
select an entry and choose **Load** or **Load and run**. Loading resets the C64,
so an existing running program is replaced. **Load and run** is available only
for entries recognised as BASIC. For machine-code entries, use **Load**, then
follow that program's start instructions; the loader does not guess a `SYS`
address. The main **Boot** button reloads the selected entry with its last run
choice. Keyboard **Reset** resets the C64 without reloading it.

Select a D64/D81 or the built-in disk to leave T64 mode. BBC modes are unchanged.

## Scope and limits

- Read-only T64 containers, versions 1.0 and 1.1; up to 64 program entries and
  1 MiB per archive. Unused directory slots are allowed.
- No cassette motor, pulse timing, `.tap`, tape recording, custom tape loaders,
  or automatic subsequent tape loads. Selecting separate programs from a T64
  does not emulate a multi-load tape game's cassette routines.
- Invalid/truncated directories, unsupported entry types, out-of-file payloads,
  overlapping payloads and invalid load ranges are rejected before replacing
  the mounted image. Historical archives with incorrect end-address metadata
  may need repair using a desktop tool; this loader does not guess their sizes.
- The archive occupies the existing mounted-media PSRAM region. Upload staging
  is separate, so an incomplete or rejected upload cannot corrupt the mounted
  archive. Nothing is written to the flash save area.

The format is documented in the [VICE file format reference](https://vice-emu.sourceforge.io/vice_17.html).
The parser is local to this project; no change to the pinned frank-c64 fork is
required. Existing Frodo/FRANK credits continue to apply to the emulator core.

## API

C64 `/api/status` includes `tape` with `generation`, `count`, `selected`, and
`state` (`none`, `ready`, `loading`, `loaded`, `cancelled`, or `error`).

`GET /api/tape` returns the current archive generation and `entries` containing
`index`, `name`, `start`, `size`, and `run`. The directory is kept out of the
regular status response to keep that response bounded.

`POST /api/tape/load` accepts three space-separated integers:
`<generation> <index> <run>` (run is 0 or 1). A stale generation returns 409;
invalid selections or unsupported automatic starts return 400. Acceptance means
loading is scheduled between emulation frames, after a reset and startup delay.

## Validation and hardware test

Parser/loader sanitizers:

```sh
cc -std=c11 -Wall -Wextra -Werror -fsanitize=address,undefined -g \
  -Isrc/machines/c64 src/machines/c64/t64.c tests/c64/t64_test.c \
  -o /tmp/t64-test
/tmp/t64-test
python3 tests/c64/t64_api_test.py
sh tests/c64/native/build.sh t64
```

The native-core test loads two generated BASIC programs and verifies that they
remain idle after **Load**, then execute correctly after `RUN`. Browser coverage
is in `tests/c64/t64_web_test.cjs` (Playwright and Chrome required).

On Presto, test a known working single-program T64 from both SD and upload; check
its startup, sound, keyboard and Nimbus controls. Also test a multi-program
archive, **Load** versus **Load and run**, **Boot** and **Reset**, then return to a
D64 and switch to Master and back. Report the archive name, selected program and
what appears on screen if a game does not start.

The owner confirmed successful T64 operation on Presto with their test image
after flashing this build. This confirms that hardware test; compatibility with
other games and the additional scenarios above still depends on testing.
